# Songr 1.4.6

This is a security release. It closes Songr's exposure to the October 2026
Node.js security fix (CVE-2026-111497, in Node's Brotli decoder) and updates
dependencies that have published security fixes. Nothing else changes.

**What to do**

- **Headless server** (installed with the install scripts, run from source, or
  installed from npm as `songr-server`): update Node.js to **22.23.4 or newer**
  (on Node 24, 24.22.1 or newer; on Node 26, 26.12.1 or newer), then update
  Songr. The install scripts now refuse older Node.js versions, and the npm
  package declares the same minimum.
- **Docker**: pull the new image (`ghcr.io/roethlar/songr:v1.4.6` or
  `:latest`) and recreate the container. The image includes a patched
  Node.js 22.
- **Desktop app**: update the app.

What changed:

- Songr's server no longer accepts compressed request bodies. Before this
  release it decoded them, so any device that could reach Songr could send
  data to Node's Brotli decoder. No Songr client sends compressed bodies, so
  nothing you use changes; such requests are now refused.
- The headless server requires a Node.js version that includes the fix, as
  above. Node.js 20, which the install scripts previously accepted, is no
  longer supported.
- Dependencies with published security fixes are updated, including the
  server's request parsing and Socket.IO, the web interface's build tools, and
  the desktop app's Electron (43.8.3).

Desktop app: the app runs Songr on the Node.js built into Electron. Electron
43.8.3 is built on Node.js 24.22.0, which predates the fix. By default the app
only accepts connections from the computer it runs on, so other devices cannot
reach it. If you have turned on **Serve on the local network** ("Allow other
devices on my network") in the app's settings, other devices on your network
can reach the app's server, which runs on that pre-fix Node.js; compressed
request bodies are refused there too. A later desktop release will move to an
Electron built on Node.js 24.22.1 or newer.

The Windows installer for this release is not code-signed. Windows may warn
that it comes from an unknown publisher; choose **More info**, then **Run
anyway**, to install.

Application identity, pairing and saved settings are retained when upgrading.
